# Bidirectional Editing

One of Seria's most powerful features is **bidirectional editing** - the ability to edit your CSV data from either the Cell View grid or the Print View formatted layout, with changes instantly reflected in both views.

---

## How It Works

### The Core Concept

When you open a CSV file in Seria:
1. The **Cell View** shows your data in a traditional spreadsheet grid
2. The **Print View** transforms that same data into a formatted layout (Screenplay, Dialogue, Corkboard, etc.)
3. **Both views display the same underlying CSV data**

When you edit in either view:
- Changes update the underlying CSV data immediately
- The other view updates in real-time to reflect the change
- No export or sync step required

Think of it like this: You have one source of truth (the CSV file), but two different ways to look at and edit it.

---

## Editing in Cell View

When you edit in the Cell View:

1. **Click a cell** and press `F2` to start editing
2. **Type your changes**
3. **Press Enter** to save

**What happens:**
- The cell value updates in the grid
- The Print View immediately updates to show the new value
- If that cell is part of a Print element (like a character line or action), the formatted text updates instantly

**Example:**
- CSV Cell: `Character` column, value "SARAH"
- Print View: Shows "SARAH" as a centered character name in screenplay format
- Edit cell to "DAVID"
- Print View instantly shows "DAVID" in the same formatted style

---

## Editing in Print View

When you edit in the Print View:

1. **Click any text** in the Print preview
2. **Type your changes** directly in the formatted view
3. **Click elsewhere** or press `Escape` to save

**What happens:**
- The formatted text updates in the Print View
- The corresponding cell in the Cell View updates immediately
- The underlying CSV file is modified

**Example:**
- Print View: Screenplay format showing "INT. COFFEE SHOP - DAY"
- Click the text and change it to "INT. SPACESHIP - NIGHT"
- Cell View instantly updates the corresponding cell to "INT. SPACESHIP - NIGHT"

---

## Why This Matters

### No Export Step

Traditional workflows often look like this:
1. Edit dialogue in a writing tool (Final Draft, etc.)
2. Export to CSV for the game engine
3. Discover an issue in-game
4. Go back to the writing tool, make the change
5. Export again

**With Seria's bidirectional editing:**
1. Edit in whichever view feels right
2. That's it - your CSV is already updated

### One Source of Truth

- Your CSV file is the only file
- No risk of version conflicts between formats
- Git-friendly (plain text CSV)
- Works with game engine pipelines directly

### Writer-Friendly Interface

- Game writers can edit in familiar screenplay/dialogue layouts
- Programmers can work in the grid view if they prefer
- No technical knowledge needed to edit formatted views

---

## Which View Should I Use?

### Use Cell View When:

- **Bulk editing** - Copy/paste multiple cells, reorder rows
- **Data operations** - Filtering, sorting, searching
- **Structural changes** - Adding/removing columns, reorganizing
- **Precise control** - Editing raw values, handling special characters

**Example use case:** "I need to filter all lines by a specific character, then bulk update a tag column."

---

### Use Print View When:

- **Writing naturally** - Dialogue, narration, action lines
- **Visual context** - See how text flows on a page
- **Creative editing** - Focus on content, not structure
- **Proofing** - Check formatting, spacing, readability

**Example use case:** "I need to write a conversation between two characters and make sure the dialogue flows naturally."

---

### Switch Freely

The power of bidirectional editing is that you don't have to choose:

1. Start writing dialogue in Print View (feels natural)
2. Switch to Cell View to filter lines by character
3. Switch back to Print View to edit the dialogue
4. Jump to Cell View to copy lines to a new scene

No export, no sync, just edit however feels right in the moment.

## Technical Details

### How Fast Is It?

**Instant.** Changes appear in both views with no perceptible delay.

### What If I Edit the Same Cell Twice?

**Last edit wins.** If you:
1. Edit a cell in Cell View
2. Immediately edit the corresponding text in Print View

...the Print View edit will overwrite the Cell View edit. Both views always show the same value.

### Does It Work With Undo?

**Yes.** Edits in either view are added to the undo history:
- `Ctrl+Z` undoes the last change, regardless of which view it was made in
- Undo history is shared between both views

### What About Complex Prints?

Some Print templates combine multiple CSV columns into a single formatted element:

**Example:**
- Print shows: `"SARAH: Hello there"` (formatted as a dialogue block)
- This comes from two CSV columns: `Character` ("SARAH") and `Dialogue` ("Hello there")

**When editing in Print View:**
- Clicking "SARAH" edits the `Character` column
- Clicking "Hello there" edits the `Dialogue` column
- The Print template determines which part maps to which column

See [Print Recipes](wiki/03_Print%20View/02.02_Print%20Recipes.md) for how templates define these mappings.

## Limitations

### Text-Only Editing

Bidirectional editing works for text content only:
- ✅ Edit character names, dialogue, descriptions
- ❌ Cannot edit formatting (font, color, size) from Print View
- ❌ Cannot edit column structure from Print View

**Workaround:** Use Cell View for structural changes, Print View for content editing.

### Print-Specific Formatting

Some Print templates add visual formatting (bold, italic, indents) that aren't in the CSV:

**Example:**
- CSV cell contains: "Hello there"
- Print View shows: "*Hello there*" (italicized)

**Editing in Print View:**
- You edit the text content ("Hello there")
- The italicization comes from the Print template, not the CSV
- You cannot edit the italics directly (it's part of the template design)

To customize Print formatting, see [Custom Recipes](wiki/04_Customization/03.04_Custom%20Recipes.md).

### Read-Only Elements

Some Print templates include read-only elements (page numbers, timestamps, etc.) that don't map to CSV data. These cannot be edited in either view.

## Tips for Effective Bidirectional Editing

**Tip 1: Learn the keyboard shortcuts**
- `Ctrl+\` - Toggle Print View (right)
- `Ctrl+/` - Toggle Print View (bottom)
- Quick switching makes editing fluid

**Tip 2: Use dual monitors**
- Cell View on one monitor
- Print View on the other
- See both simultaneously

**Tip 3: Start in Print View, finish in Cell View**
- Write naturally in Print View
- Polish and organize in Cell View

**Tip 4: Trust the sync**
- Don't manually "refresh" - changes are instant
- Don't worry about saving after each edit - just keep working

## Common Workflows

### Dialogue Writing

1. Open Print View in Screenplay or Dialogue format
2. Click where you want to add a line
3. Type the character name, then the dialogue
4. Move to next line and repeat
5. Switch to Cell View to bulk tag lines or filter by character

### Quest Design

1. Use Cell View to enter quest names, objectives, rewards (structured data)
2. Switch to Print View (custom Quest template) to proof the layout
3. Edit quest descriptions in Print View where you can see them formatted
4. Switch back to Cell View for technical fields (IDs, tags)

### Item Database

1. Enter items in Cell View (names, stats, IDs)
2. Switch to Record or Corkboard Print View
3. Edit flavor text and descriptions in the visual cards
4. Review in Print View, tweak numbers in Cell View
