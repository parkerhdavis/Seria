## Development Setup

### Prerequisites

**Required:**
- **Node.js 18+** - [Download](https://nodejs.org/)
- **Rust** - Installed automatically by setup script, or [install manually](https://rustup.rs/)
- **Git** - For version control

**Linux Only:**
System dependencies for Tauri 2.0 (Ubuntu/Debian):
```bash
sudo apt install libwebkit2gtk-4.1-dev \
    build-essential \
    curl \
    wget \
    file \
    libssl-dev \
    libgtk-3-dev \
    libayatana-appindicator3-dev \
    librsvg2-dev
```

For other distributions, see [Tauri prerequisites](https://v2.tauri.app/start/prerequisites/).

### Initial Setup

1. **Clone the repository:**
```bash
git clone https://gitlab.com/parkerhdavis/Seria.git
cd Seria
```

2. **Run setup script:**
```bash
make setup
```

This will:
- Install Rust (if not already installed)
- Install Node.js dependencies
- Verify system dependencies (Linux only)

3. **Verify setup:**
```bash
make dev
```

The Seria window should open with hot-reload enabled.

### Key Directories

**Frontend (`frontend/src/`):**
- All application UI and business logic
- React components, state management, utilities
- No backend-specific code

**Backend (`backend/src/`):**
- Rust code (~1500 lines total across 5 files)
- Handles file I/O, storage persistence, CSV diff comparison, and screenplay conversion
- Exposes 16 Tauri commands to frontend

**Resources (`resources/`):**
- Platform-specific files (.desktop, icons, etc.)
- Installation guides for different platforms

## Development Workflow

### Starting Development Server

```bash
make dev
```

This starts:
- Vite dev server (frontend) with hot-reload
- Tauri development window with Rust hot-reload

**Faster UI iteration (without Tauri):**
```bash
make dev-frontend
```

This only starts the Vite dev server. Good for rapid UI changes that don't need Tauri features.

### Making Changes

**Frontend changes (React/TypeScript):**
1. Edit files in `frontend/src/`
2. Save - Vite hot-reload updates automatically
3. Check browser console for errors

**Backend changes (Rust):**
1. Edit files in `backend/src/`
2. Save - Tauri rebuilds and restarts
3. Check terminal output for compile errors

### Testing Changes

```bash
make test
```

Runs both frontend (Vitest) and backend (Cargo test) tests.

### Code Quality

**Lint code:**
```bash
make lint
```

**Format code:**
```bash
make format
```

**Build production version:**
```bash
make build
```

Creates platform-specific installer in `target/release/bundle/`.

## Coding Standards

### General

- **4-space indents** (not 2-space)
- **Double quotes** for strings
- **Comprehensive comments** on all files, classes, and complex logic
- Follow existing code style in each file

### TypeScript/React

- Use **functional components** with hooks (no class components)
- Use **TypeScript interfaces** for all props and state
- **Name components** in PascalCase: `CellGridVirtualized.tsx`
- **Name utilities** in camelCase: `cellParser.ts`
- Add **JSDoc comments** to all exported functions

**Example:**
```typescript
/**
 * Parses a CSV string into a 2D array.
 *
 * @param csvText - Raw CSV text content
 * @param hasHeader - Whether the first row is a header
 * @returns Parsed CSV data as 2D string array
 */
export function parseCSV(csvText: string, hasHeader: boolean): string[][] {
    // Implementation
}
```

### Styling

- Use **DaisyUI components** wherever possible
- Use **semantic utilities**: `bg-base-100`, `text-primary`, etc.
- **Never hard-code colors** - use CSS variables or DaisyUI classes
- Support **both light and dark themes**

### Rust

- Keep Rust code **minimal** - only for file I/O
- Use `Result<T, String>` for all Tauri commands
- Add **doc comments** to all public functions
- Follow Rust standard formatting (`rustfmt`)

**Example:**
```rust
/// Opens a cell file (CSV/TSV/JSON) and returns its contents as a string.
///
/// # Arguments
/// * `path` - Absolute path to the file
///
/// # Returns
/// * `Ok(String)` - File contents
/// * `Err(String)` - Error message
#[tauri::command]
fn open_cell_file(path: String) -> Result<String, String> {
    // Implementation
}
```

### ESLint Disable Comments

When using `eslint-disable-next-line`, **always document:**
1. What error is being disabled
2. Why it's being disabled
3. What alternatives exist

**Example:**
```typescript
// eslint-disable-next-line react-hooks/exhaustive-deps
// Disabled: Missing handleStartEdit dependency
// Reason: handleStartEdit is stable, adding would cause infinite loop
// Alternative: Wrap in useCallback, then add to dependencies
```

## Testing

### Running Tests

**All tests:**
```bash
make test
```

**Frontend only (Vitest):**
```bash
cd frontend && npm run test
```

**Backend only (Rust):**
```bash
cd backend && cargo test
```

### Writing Tests

**Frontend (Vitest + React Testing Library):**

Test files live in `frontend/src/__tests__/`:

```typescript
import { describe, it, expect } from "vitest";
import { calculateSummary } from "@utils/summaryCalculations";

describe("calculateSummary", () => {
    it("counts non-empty values", () => {
        const result = calculateSummary(["a", "b", "", "c"], "count");
        expect(result).toBe("3");
    });
});
```

**Backend (Rust):**

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_scene_heading_detection() {
        assert!(is_scene_heading("INT. OFFICE - DAY"));
        assert!(is_scene_heading("EXT. PARK - NIGHT"));
        assert!(!is_scene_heading("Just some action text"));
    }
}
```

### Test Files

Sample data files are in `resources/`:
- `sample_aae_onescene.csv` - All About Eve single scene (quick testing)
- `sample_aae_fullscript.csv` - All About Eve full screenplay (comprehensive testing)
- `sample_aae_script10x.csv` - 10x duplicated screenplay (performance testing)
- `sample_aae_fulltext.txt` - Plain text screenplay (converter testing)

Frontend tests are in `frontend/src/__tests__/utils/`:
- `cellParser.test.ts` - CSV/TSV parsing tests
- `dataTransformationPipeline.test.ts` - Data pipeline tests
- `screenplayUtils.test.ts` - Screenplay utility tests
- `summaryCalculations.test.ts` - Column summary tests

Backend tests are in `backend/src/`:
- `diff.rs` - 5 tests for CSV diff comparison
- `converters/screenplay.rs` - 7 tests for screenplay conversion
