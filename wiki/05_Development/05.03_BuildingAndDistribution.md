## Prerequisites

### All Platforms

**Required:**
- Node.js 18+
- Rust (via rustup)
- Git

### Linux

**Ubuntu/Debian:**
```bash
sudo apt install libwebkit2gtk-4.1-dev \
    build-essential \
    curl \
    wget \
    file \
    libssl-dev \
    libgtk-3-dev \
    libayatana-appindicator3-dev \
    librsvg2-dev
```

**Fedora:**
```bash
sudo dnf install webkit2gtk4.1-devel \
    openssl-devel \
    curl \
    wget \
    file \
    libappindicator-gtk3-devel \
    librsvg2-devel
```

**Arch:**
```bash
sudo pacman -S webkit2gtk \
    base-devel \
    curl \
    wget \
    file \
    openssl \
    appmenu-gtk-module \
    gtk3 \
    libappindicator-gtk3 \
    librsvg
```

### Windows

- **Node.js** - Install from nodejs.org
- **Rust** - Install via rustup-init.exe
- **WebView2** - Usually pre-installed on Windows 10/11
- **Visual Studio Build Tools** - Installed automatically by Rust

### macOS

- **Xcode Command Line Tools:**
  ```bash
  xcode-select --install
  ```
- **Node.js** - Install via Homebrew or nodejs.org
- **Rust** - Install via rustup

## Building for Development

### Quick Start

```bash
# Clone repository
git clone https://gitlab.com/parkerhdavis/Seria.git
cd Seria

# Install dependencies
make setup

# Start development server
make dev
```

This starts both Vite (frontend) and Tauri (backend) with hot-reload enabled.

### Development Commands

```bash
make dev              # Start full dev server (Vite + Tauri)
make dev-frontend     # Start Vite only (faster for UI work)
make lint             # Run linting
make format           # Format code
make test             # Run tests
make check            # Run Rust compiler checks without building
```

## Building for Production

### Build Command

```bash
make build
```

This:
1. Builds the frontend (Vite)
2. Builds the Rust backend
3. Creates platform-specific installers

**Output location:** `target/release/bundle/`

### Build Artifacts

The build creates different artifacts depending on your platform:

**Linux:**
- `.deb` - Debian/Ubuntu package
- `.rpm` - Fedora/RHEL/openSUSE package
- `.AppImage` - Universal Linux binary

**Windows:**
- `.msi` - Windows Installer (MSI)
- `_setup.exe` - NSIS Installer

**macOS:**
- `.dmg` - macOS Disk Image
- `.app` - Application bundle

## Platform-Specific Builds

### Linux Builds

#### Debian/Ubuntu Package (.deb)

**Build on Ubuntu/Debian:**
```bash
make build
```

**Output:** `target/release/bundle/deb/Seria_0.1.0_amd64.deb`

**Test installation:**
```bash
sudo dpkg -i target/release/bundle/deb/Seria_*.deb
Seria
```

**Uninstall:**
```bash
sudo dpkg -r Seria
```

#### RPM Package (.rpm)

**Build on Fedora/RHEL/openSUSE:**
```bash
make build
```

**Output:** `target/release/bundle/rpm/Seria-0.1.0-1.x86_64.rpm`

**Test installation:**
```bash
sudo rpm -i target/release/bundle/rpm/Seria-*.rpm
Seria
```

**Uninstall:**
```bash
sudo rpm -e Seria
```

#### AppImage

**Build:**
```bash
make build
```

**Output:** `target/release/bundle/appimage/Seria_0.1.0_amd64.AppImage`

**Test:**
```bash
chmod +x target/release/bundle/appimage/Seria_*.AppImage
./target/release/bundle/appimage/Seria_*.AppImage
```

**Note:** AppImage requires FUSE to run. See [troubleshooting](#appimage-wont-run).

### Windows Builds

**Build on Windows:**
```powershell
# PowerShell
.\setup.sh
cd backend
..\frontend\node_modules\.bin\tauri build
```

Or using Make (if installed):
```bash
make build
```

**Outputs:**
- `target/release/bundle/msi/Seria_0.1.0_x64_en-US.msi`
- `target/release/bundle/nsis/Seria_0.1.0_x64-setup.exe`

**Test installation:**
1. Double-click the `.msi` or `_setup.exe` file
2. Follow installation wizard
3. Launch from Start Menu

### macOS Builds

**Build on macOS:**
```bash
make build
```

**Outputs:**
- `target/release/bundle/dmg/Seria_0.1.0_x64.dmg`
- `target/release/bundle/macos/Seria.app`

**Test installation:**
1. Open the `.dmg` file
2. Drag `Seria.app` to Applications folder
3. Launch from Applications or Spotlight

**Note:** First launch requires right-click → Open to bypass Gatekeeper.

## Cross-Platform Builds

### Building Linux Packages on Linux

You can build different Linux package formats on the same machine:

**Build all Linux formats:**
```bash
make build-linux
```

This creates AppImage, DEB, and RPM packages in a single build.

**Build individual formats:**
```bash
# Just AppImage
cd backend && ../frontend/node_modules/.bin/tauri build --target appimage

# Just DEB
cd backend && ../frontend/node_modules/.bin/tauri build --target deb

# Just RPM
cd backend && ../frontend/node_modules/.bin/tauri build --target rpm
```

### Building for Other Platforms

**Cross-compilation is not officially supported by Tauri.** To build for a specific platform, you must build on that platform.

**Recommended approach: GitLab CI/CD**
- Set up GitLab runners for Windows and macOS (see [CI/CD Pipeline](#cicd-pipeline))
- Push a git tag to trigger automated builds for all platforms
- Download artifacts from GitLab pipelines or releases

**Alternative approaches:**
- Use virtual machines for each platform (VMware, Parallels, VirtualBox)
- Dual-boot or multiple physical machines
- Cloud build services with Windows/macOS support

**Platform-specific Makefile commands:**
```bash
# On Linux
make build-linux       # AppImage, DEB, RPM

# On Windows
make build-windows     # MSI, NSIS

# On macOS
make build-macos       # DMG, APP
```

**Note:** Running `make build` on any platform builds installers for that platform only.

## Configuring Builds

### Build Configuration

Edit `backend/tauri.conf.json` to configure build options:

```json
{
    "productName": "Seria",
    "version": "0.1.0",
    "identifier": "com.Seria.csveditor",
    "bundle": {
        "active": true,
        "targets": ["appimage", "deb", "rpm", "msi", "nsis", "dmg", "app"],
        "icon": [
            "icons/32x32.png",
            "icons/128x128.png",
            "icons/icon@2x.png",
            "icons/icon.png"
        ]
    }
}
```

**Key options:**
- `productName` - Application display name
- `version` - Application version (synced from `.env` - see [Project Quirks](05.06_ProjectQuirks.md))
- `identifier` - Unique app identifier (reverse domain notation)
- `bundle.targets` - Which bundle formats to build

### Build Environment Variables

**.env file** (in project root):
```bash
# Vite configuration
VITE_APP_NAME=Seria
VITE_APP_VERSION=0.1.0

# Additional build options
TAURI_PRIVATE_KEY=...   # For auto-updates (optional)
TAURI_KEY_PASSWORD=...  # For auto-updates (optional)
```

## Troubleshooting Builds

### Common Build Errors

#### "WebView2 not found" (Windows)

**Error:** WebView2 runtime not installed

**Solution:**
Download and install from [Microsoft WebView2](https://developer.microsoft.com/en-us/microsoft-edge/webview2/)

#### "webkit2gtk not found" (Linux)

**Error:** Missing WebKitGTK dependency

**Solution:**
```bash
# Ubuntu/Debian
sudo apt install libwebkit2gtk-4.1-dev

# Fedora
sudo dnf install webkit2gtk4.1-devel

# Arch
sudo pacman -S webkit2gtk
```

#### "Command not found: tauri" (All platforms)

**Error:** Tauri CLI not installed

**Solution:**
```bash
cd frontend
npm install
```

The Tauri CLI is installed as a dev dependency in `frontend/package.json`.

#### AppImage won't run (Linux)

**Error:** FUSE error when launching AppImage

**Solution:**
```bash
# Ubuntu/Debian
sudo apt install fuse libfuse2

# Fedora
sudo dnf install fuse fuse-libs

# Arch
sudo pacman -S fuse2
```

#### Build is very slow (All platforms)

**Cause:** First Rust build compiles all dependencies

**Solutions:**
- First build can take 5-10 minutes (normal)
- Subsequent builds are much faster (~1 minute)
- Use `make check` to verify code without full build
- Use `make dev` for incremental builds during development

#### "Out of memory" during build (Linux/Low RAM)

**Solution:**
```bash
# Reduce Rust parallel jobs
export CARGO_BUILD_JOBS=2
make build
```

Or increase swap space:
```bash
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
```

## Distribution

### Versioning

**IMPORTANT:** Version management in Seria uses a single source of truth pattern. See [Project Quirks](05.06_ProjectQuirks.md) for details on how version numbers are managed.

**Version format:** Follow [Semantic Versioning](https://semver.org/)
- `MAJOR.MINOR.PATCH`
- Example: `0.1.0` → `0.2.0` (new features) → `0.2.1` (bug fix)

### Creating a Release

1. **Update version number** in `.env` (see [Project Quirks](05.06_ProjectQuirks.md))
2. **Update CHANGELOG.md** with release notes
3. **Commit version changes:**
   ```bash
   git add .env CHANGELOG.md
   git commit -m "Release v0.2.0"
   git tag v0.2.0
   ```
4. **Build on each platform:**
   ```bash
   make build
   ```
5. **Test installers** on clean machines
6. **Push to GitLab:**
   ```bash
   git push origin main
   git push origin v0.2.0
   ```
7. **Create GitLab Release:**
   - Go to Repository → Tags → v0.2.0
   - Click "Edit release notes"
   - Upload build artifacts
   - Add release notes

### File Naming Convention

**Linux:**
- `Seria_0.2.0_amd64.deb`
- `Seria-0.2.0-1.x86_64.rpm`
- `Seria_0.2.0_amd64.AppImage`

**Windows:**
- `Seria_0.2.0_x64_en-US.msi`
- `Seria_0.2.0_x64-setup.exe`

**macOS:**
- `Seria_0.2.0_x64.dmg`

### Checksums

Generate SHA256 checksums for all build artifacts:

```bash
# Linux/macOS
cd target/release/bundle/
sha256sum **/*.{deb,rpm,AppImage,msi,exe,dmg} > SHA256SUMS

# Windows (PowerShell)
Get-FileHash *.msi, *.exe -Algorithm SHA256 | Format-List
```

Include `SHA256SUMS` file with the release.

### Code Signing

**Status:** Seria builds are currently **unsigned**.

**Implications:**
- Windows: SmartScreen warning
- macOS: Gatekeeper warning
- Linux: No issues (AppImage, deb, rpm work unsigned)

**Future:** Code signing certificates cost $300-500/year. May add if funding allows.

## CI/CD Pipeline

Seria uses GitLab CI/CD for automated multi-platform builds. The pipeline is configured in `.gitlab-ci.yml` at the project root.

### Pipeline Overview

**Stages:**
1. **Test** - Linting and code quality checks
2. **Build** - Platform-specific builds (Linux, Windows, macOS)
3. **Release** - Automated release creation with artifacts

### Triggers

**Merge Requests:**
- Runs linting on all merge requests
- Prevents merging if linting fails

**Main Branch:**
- Builds all platforms (Linux, Windows, macOS)
- Stores artifacts for 30 days

**Tags:**
- Builds all platforms
- Creates GitLab release with installers
- Generates download links for all artifacts

### Platform Runners

The pipeline requires GitLab runners for each platform:

**Linux Runner:**
- Ubuntu 22.04 image (uses Docker)
- Builds AppImage, DEB, and RPM packages
- Always available (uses shared GitLab runners)

**Windows Runner:**
- Requires self-hosted Windows runner with `windows` tag
- Builds MSI and NSIS installers
- Must have Rust, Node.js, and Chocolatey installed

**macOS Runner:**
- Requires self-hosted macOS runner with `macos` tag
- Builds DMG and APP bundles
- Must have Xcode, Homebrew, Rust, and Node.js installed

### Setting Up Runners

**For Windows and macOS builds, you need to configure self-hosted runners:**

1. Go to Settings → CI/CD → Runners in your GitLab project
2. Follow the instructions to install GitLab Runner on Windows/macOS
3. Register the runner with the appropriate tag (`windows` or `macos`)
4. Install prerequisites (Rust, Node.js, platform SDKs)

**Alternative:** If you don't have access to Windows/macOS machines, you can:
- Use cloud CI services (e.g., GitLab SaaS runners with appropriate tags)
- Build manually on each platform and upload artifacts
- Use the Makefile commands for local builds

### Creating a Release via CI/CD

**Automated release (recommended):**
```bash
# Update version numbers
git add .env
git commit -m "Release v0.2.0"
git tag v0.2.0
git push origin main
git push origin v0.2.0
```

The pipeline will:
1. Build for all platforms
2. Create a GitLab release
3. Upload all installers as release assets
4. Generate download links

**Manual release:**
If CI/CD runners are not available for all platforms, you can build locally:
```bash
# On Linux
make build-linux

# On Windows
make build-windows

# On macOS
make build-macos
```

Then manually upload artifacts to GitLab releases.

### Pipeline Configuration

The `.gitlab-ci.yml` file defines:
- Build dependencies for each platform
- Artifact storage locations
- Cache configuration for faster builds
- Release automation

**Key features:**
- Caches dependencies (npm and Cargo) for faster builds
- Runs only on relevant branches (main, tags, merge requests)
- Stores build artifacts for 30 days
- Automatically creates releases with download links

### Monitoring Builds

**View pipeline status:**
- Go to CI/CD → Pipelines in GitLab
- Click on a pipeline to see individual job status
- Click on a job to view build logs

**Download artifacts:**
- Go to CI/CD → Pipelines
- Click the download button next to a successful job
- Or access via GitLab releases for tagged versions

### Troubleshooting CI/CD

**Linux build fails:**
- Check that system dependencies are installed in the Docker image
- Verify the Ubuntu version (22.04 required for webkit2gtk-4.1)

**Windows/macOS build fails with "No runner available":**
- Ensure you have registered self-hosted runners with the correct tags
- Check that the runners are online in Settings → CI/CD → Runners

**Build timeout:**
- First builds can take 10-15 minutes (compiling Rust dependencies)
- Increase timeout in Settings → CI/CD → General pipelines if needed
- Cache should make subsequent builds much faster (~2-5 minutes)
