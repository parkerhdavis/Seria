# Testing Persistent Data

Guide for testing Seria's file configuration persistence system during development and before releases.

---

## Quick Reference

**Dev mode config location:**
```bash
# Linux
~/.local/share/com.Seria.app/file-configs.json

# macOS
~/Library/Application Support/com.Seria.app/file-configs.json

# Windows
%LOCALAPPDATA%\com.Seria.app\file-configs.json
```

**Quick test:**
```bash
# View config file (Linux/macOS)
cat ~/.local/share/com.Seria.app/file-configs.json | jq .

# Watch for changes
watch -n 1 'cat ~/.local/share/com.Seria.app/file-configs.json 2>/dev/null | jq ".configs | length"'
```

---

## Overview

Seria's persistent data storage works identically in both development mode (`make dev`) and production builds. You can (and should) do most testing in dev mode for rapid iteration, then validate with a compiled build before release.

---

## Development Mode Testing

### Where Dev Mode Stores Data

Tauri creates a **separate app data directory for development** to avoid conflicts with production builds.

**Development paths:**
- **Windows:** `%LOCALAPPDATA%\com.Seria.app\file-configs.json`
- **macOS:** `~/Library/Application Support/com.Seria.app/file-configs.json`
- **Linux:** `~/.local/share/com.Seria.app/file-configs.json`

**Production paths:**
- **Windows:** `%LOCALAPPDATA%\Seria\file-configs.json`
- **macOS:** `~/Library/Application Support/Seria/file-configs.json`
- **Linux:** `~/.local/share/Seria/file-configs.json`

**Important Notes:**
- The exact directory name depends on the `identifier` field in `tauri.conf.json` (currently `com.Seria.app`)
- **Linux uses `~/.local/share/` not `~/.config/`** - This is correct per XDG Base Directory spec
- Both dev and production use the same base path; only the app identifier differs

## Basic Functionality Tests

### Test 1: Basic Config Persistence

```bash
# Start dev mode
make dev
```

**In the application:**
1. Open a CSV file (e.g., `testing/characters.csv`)
2. Resize some columns by dragging column edges
3. Toggle settings:
   - Wrap Text (on/off)
   - Auto-Fit (on/off)
   - Column Lines (on/off)
   - Row Coloring mode
4. Add a column filter (e.g., "Name contains 'John'")
5. Close the file (File menu → Close File)
6. Reopen the same file

**Expected result:**
- ✓ Column widths are restored
- ✓ All settings toggles match previous state
- ✓ Column filter is still active
- ✓ Console logs show: `"Applied file config: <uuid>"`

**If it fails:**
- Check browser DevTools console for errors
- Verify config file exists (see "Verify Config File Creation" below)
- Check that `autoSaveConfigs` is enabled in fileConfigStore

### Test 2: Verify Config File Creation

**Linux/macOS:**
```bash
# View the config file
cat ~/.local/share/com.Seria.app/file-configs.json | jq .

# Or just check if it exists
ls -lh ~/.local/share/com.Seria.app/file-configs.json

# Count number of configs
cat ~/.local/share/com.Seria.app/file-configs.json | jq '.configs | length'
```

**Windows PowerShell:**
```powershell
# View the config file
Get-Content $env:LOCALAPPDATA\com.Seria.app\file-configs.json | ConvertFrom-Json

# Check if it exists
Test-Path $env:LOCALAPPDATA\com.Seria.app\file-configs.json

# Count number of configs
(Get-Content $env:LOCALAPPDATA\com.Seria.app\file-configs.json | ConvertFrom-Json).configs.Count
```

**Expected JSON structure:**
```json
{
  "version": 1,
  "configs": [
    {
      "id": "uuid-123-456-789",
      "identifiers": {
        "absolutePath": "/path/to/test.csv",
        "filename": "test.csv",
        "parentDir": "test-data",
        "fileSize": 1234,
        "contentHashPartial": "abc123...",
        "osFileId": "inode-56789"
      },
      "lastSeen": "2025-11-12T21:30:00.000Z",
      "config": {
        "columnWidths": { "0": 200, "1": 150 },
        "wrapText": false,
        "autoFitColumns": true
      }
    }
  ]
}
```

### Test 3: File Rename Persistence (OS File ID Matching)

**In dev mode:**
1. Open `testing/sample.csv`
2. Resize columns to specific widths
3. Set Wrap Text to ON
4. Note the file path displayed in the app header
5. Close the file

**In OS file explorer:**
```bash
# Rename the file
cd testing
mv sample.csv sample-renamed.csv
```

**Back in dev mode:**
1. Open `testing/sample-renamed.csv`

**Expected result:**
- ✓ Column widths are preserved
- ✓ Wrap Text is still ON
- ✓ Console logs show: `"Config found via OS file ID match"`

**Why this works:**
- File's inode (Unix/Mac) or File ID (Windows) doesn't change on rename
- Seria matches via OS file ID even though path changed

### Test 4: File Move Persistence (Content Hash Matching)

**In dev mode:**
1. Open `testing/characters.csv`
2. Configure multiple settings (column widths, filters, row coloring)
3. Close the file

**In OS file explorer:**
```bash
# Move file to a different directory
mkdir ~/Desktop/temp-test
cp testing/characters.csv ~/Desktop/temp-test/
```

**Back in dev mode:**
1. Open `~/Desktop/temp-test/characters.csv`

**Expected result:**
- ✓ Settings are restored
- ✓ Console logs show one of:
  - `"Config found via filename + parent + size match"` (if file is small)
  - `"Config found via content hash match"` (if file is >100KB)

**Note:** If you **move** (not copy) on the same volume, OS file ID might still match. Use copy to fully test hash matching.

### Test 5: Auto-Save Debouncing

**Purpose:** Verify configs don't save on every tiny change (performance optimization)

**In the application:**
1. Open a CSV file
2. Rapidly resize a column back and forth (drag edge 10 times quickly)
3. Wait 2 seconds

**Expected result:**
- ✓ Console shows single `"Saved file config"` after 1 second delay
- ✓ Multiple rapid changes are batched into one save

### Test 6: Multiple Files Tracking

**In dev mode:**
1. Open `file-a.csv`, resize columns, close
2. Open `file-b.csv`, set different column widths, close
3. Open `file-c.csv`, apply filters, close
4. Reopen each file in reverse order (c, b, a)

**Expected result:**
- ✓ Each file restores its own unique settings
- ✓ Config file has 3 entries with different UUIDs
- ✓ No cross-contamination of settings between files

**Verify:**
```bash
cat ~/.local/share/com.Seria.app/file-configs.json | jq '.configs | length'
# Should output: 3
```

### Test 7: Export/Import Functionality

**Export test:**
1. Open Settings (Ctrl+,)
2. Scroll to "File Configuration Management"
3. Click "Export Configs"
4. Save to `~/Desktop/test-export.json`

**Verify export:**
```bash
cat ~/Desktop/test-export.json | jq .
# Should show valid JSON with version, exported timestamp, and configs array
```

**Import test:**
1. Delete or rename the config file:
   ```bash
   mv ~/.local/share/com.Seria.app/file-configs.json ~/.local/share/com.Seria.app/file-configs.json.backup
   ```
2. In Settings modal, click "Import Configs"
3. Select `~/Desktop/test-export.json`
4. Reopen a CSV file that had saved configs

**Expected result:**
- ✓ Settings are restored from imported file
- ✓ New `file-configs.json` is created with imported data
- ✓ Console logs show: `"Configs imported from: <path>"`

**Restore backup:**
```bash
mv ~/.local/share/com.Seria.app/file-configs.json.backup ~/.local/share/com.Seria.app/file-configs.json
```

### Test 8: Cleanup Old Configs

**Setup:**
1. Manually edit the config file to add old timestamps:
   ```bash
   # Open in editor
   nano ~/.local/share/com.Seria.app/file-configs.json
   ```
2. Change `lastSeen` for one config to 200 days ago:
   ```json
   "lastSeen": "2024-04-26T00:00:00.000Z"
   ```

**In Settings modal:**
1. Click "Cleanup Old Configs"

**Expected result:**
- ✓ Console logs show: `"Cleaned up 1 old config(s)"`
- ✓ Config file no longer contains the old entry
- ✓ Recent configs (< 180 days) are preserved

**Verify:**
```bash
cat ~/.local/share/com.Seria.app/file-configs.json | jq '.configs[].lastSeen'
# All timestamps should be recent
```

## Real-Time Monitoring During Dev

**Linux/macOS - Watch config file changes:**
```bash
# Terminal 1: Start dev mode
make dev

# Terminal 2: Watch config file
watch -n 1 'echo "=== Config Stats ===" && \
ls -lh ~/.local/share/com.Seria.app/ && \
echo -e "\n=== Number of Configs ===" && \
cat ~/.local/share/com.Seria.app/file-configs.json 2>/dev/null | jq ".configs | length" && \
echo -e "\n=== Last Modified ===" && \
stat -c %y ~/.local/share/com.Seria.app/file-configs.json 2>/dev/null'
```

**What you'll see:**
- File size grows as you configure more files
- Number of configs increases
- Timestamp updates when auto-save triggers

## Debugging in Dev Mode

### Check Store State

**Open browser DevTools console (Ctrl+Shift+I):**

```javascript
// Check if configs are loaded
useFileConfigStore.getState().configData
// Should show: { version: 1, configs: [...] }

// Check number of configs
useFileConfigStore.getState().configData?.configs.length
// Should match your test file count
```

### Common Dev Mode Issues

**Issue: Config file not created**

**Diagnosis:**
```bash
# Check if directory exists
ls -la ~/.local/share/com.Seria.app/

# If not, Tauri might have failed to create it
```

**Solutions:**
1. Ensure parent directory has write permissions
2. Check console for Rust errors about file creation
3. Manually create directory and retry:
   ```bash
   mkdir -p ~/.local/share/com.Seria.app/
   ```

**Issue: Settings not persisting**

**Check:**
1. Browser console for errors
2. File actually exists and is writable
3. Auto-save is enabled
4. You're reopening the **same** file (not a copy)

**Issue: Wrong settings applied to file**

**Cause:** Multiple files with same name/size/parent directory

**Check:**
```bash
cat ~/.local/share/com.Seria.app/file-configs.json | jq '.configs[] | .identifiers.filename' | sort | uniq -c
# Look for duplicate filenames
```

**Solution:**
- Rename one of the duplicate files
- Manually delete incorrect config entry from JSON
- Add content to file to change its hash

## Production Build Testing

### When to Test with Compiled Build

Test with a production build when:

1. **Testing Production Paths**
   - Verify actual production data directory location
   - Ensure no dev-specific paths are hardcoded

2. **Testing App Updates**
   - Verify configs persist across app version upgrades
   - Test config schema migrations (if any)

3. **Testing Cross-Platform**
   - Build for Windows/Mac/Linux
   - Verify OS file ID generation on each platform
   - Test path handling differences (/ vs \)

4. **Performance Testing**
   - Production builds are optimized (smaller, faster)
   - Measure real-world save/load times
   - Test with large config files (100+ entries)

5. **User Acceptance Testing**
   - Final validation before release
   - Test the actual installer/package users will get

### Building for Production Testing

```bash
# Build production bundle
make build

# Artifacts created in:
# Linux: target/release/bundle/deb/
# macOS: target/release/bundle/dmg/
# Windows: target/release/bundle/msi/
```

### Production Testing Checklist

**After installing production build:**

- [ ] Verify config directory is created on first run
- [ ] Open a CSV file, configure settings, close
- [ ] Check production config path:
  - Linux: `~/.local/share/Seria/file-configs.json`
  - macOS: `~/Library/Application Support/Seria/file-configs.json`
  - Windows: `%LOCALAPPDATA%\Seria\file-configs.json`
- [ ] Reopen file, verify settings restored
- [ ] Test export/import from production path
- [ ] Test app update (install newer version over existing)
- [ ] Verify configs survive app update
- [ ] Uninstall app, verify configs remain (for user preference)

## Performance Testing

### Measuring Save Performance

```javascript
// In browser console
const start = performance.now()
await saveCurrentFileConfig()
const end = performance.now()
console.log(`Save took ${end - start}ms`)
// Should be < 50ms for typical configs
```

### Measuring Load Performance

```javascript
// In browser console
const start = performance.now()
await useFileConfigStore.getState().loadConfigs()
const end = performance.now()
console.log(`Load took ${end - start}ms`)
// Should be < 100ms for configs with 10-50 entries
// Should be < 500ms for configs with 100+ entries
```

## Test Data Recommendations

**Create a `testing/` directory with:**

1. **Small file (<100KB):** `small.csv` - 10 rows, 5 columns
   - Tests basic persistence without hash generation

2. **Large file (>100KB):** `large.csv` - 1000+ rows
   - Tests content hash generation and matching

3. **Duplicate filename:** `data/test.csv` and `backup/test.csv`
   - Tests disambiguation via parent directory

4. **Special characters:** `file with spaces.csv`, `test (2).csv`
   - Tests path handling edge cases

## Testing Checklist for Releases

**Before releasing a new version:**

- [ ] Run all basic functionality tests (Tests 1-8 above)
- [ ] Build production bundle for all platforms
- [ ] Test config persistence on each platform
- [ ] Test config migration from previous version
- [ ] Test export/import on each platform
- [ ] Verify no config data loss on app update
- [ ] Document any breaking changes to config format
- [ ] Update config version number if schema changed
- [ ] Test with real user data

## Troubleshooting Reference

| Symptom | Likely Cause | Solution |
|---------|--------------|----------|
| Config file not created | Directory permissions | Check write access to app data dir |
| Settings don't persist | Auto-save disabled | Check `preferences.autoSaveConfigs` |
| Wrong settings applied | Duplicate filenames | Check for name collisions in config file |
| Settings lost on rename | OS file ID not working | Verify Rust file ID generation on platform |
| Export/Import fails | JSON format error | Validate JSON structure with `jq` |
| Slow load times | Too many configs | Run cleanup, check file size |
| Config file corrupted | Manual edit error or crash during write | Restore from export or delete and recreate |

## Useful Commands Reference

**View config file (formatted):**
```bash
# Linux/macOS
cat ~/.local/share/com.Seria.app/file-configs.json | jq .

# Windows PowerShell
Get-Content $env:LOCALAPPDATA\com.Seria.app\file-configs.json | ConvertFrom-Json | ConvertTo-Json
```

**Backup config file:**
```bash
# Linux/macOS
cp ~/.local/share/com.Seria.app/file-configs.json ~/Seria-configs-backup-$(date +%Y%m%d).json

# Windows PowerShell
Copy-Item $env:LOCALAPPDATA\com.Seria.app\file-configs.json "$env:USERPROFILE\Desktop\Seria-configs-backup-$(Get-Date -Format 'yyyyMMdd').json"
```

**Reset all configs (start fresh):**
```bash
# Linux/macOS
rm ~/.local/share/com.Seria.app/file-configs.json

# Windows PowerShell
Remove-Item $env:LOCALAPPDATA\com.Seria.app\file-configs.json
```

**Search for specific file in configs:**
```bash
cat ~/.local/share/com.Seria.app/file-configs.json | jq '.configs[] | select(.identifiers.filename == "characters.csv")'
```

## Recommended Testing Workflow

**Daily development:**
1. Use `make dev` exclusively
2. Test each feature as you build it
3. Monitor console logs for errors
4. Use browser DevTools for debugging

**Before committing:**
1. Run through basic functionality tests (Tests 1-4)
2. Verify no console errors
3. Check config file has expected structure

**Before release:**
1. Build production bundle
2. Test on target platform(s)
3. Run full testing checklist
4. Test with production build for 24-48 hours

**After release:**
1. Monitor user reports for persistence issues
2. Check issue tracker for platform-specific bugs
3. Plan fixes for next patch release
